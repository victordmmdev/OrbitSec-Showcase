# OrbitSEC public roadmap

This roadmap communicates product direction without exposing private implementation plans, security internals, or delivery commitments. Status reflects the development snapshot used to prepare this showcase.

## Status legend

- ✅ Available in the development preview
- 🚧 In active development
- 📋 Planned
- 🔬 Exploration

## Milestone 1 — Trusted visual investigation slice

**Status: ✅ Available in the development preview**

Goal: prove that structured security-tool observations can drive a useful and traceable visual workspace.

- ✅ Tauri desktop shell for Kali Linux.
- ✅ React and TypeScript investigation interface.
- ✅ Rust backend boundary.
- ✅ Authorized project scope model.
- ✅ Strict Nmap XML import budgets and rejection behavior.
- ✅ Typed host and service events with provenance.
- ✅ 3D host/service universe.
- ✅ Accessible facts panel sharing the same investigation state.
- ✅ Selection synchronization and reduced-motion support.
- ✅ Synthetic parser and UI fixtures.
- ✅ Automated frontend and Rust verification.

## Milestone 2 — Protected local projects

**Status: 🚧 In active development**

Goal: save and reopen sensitive lab projects locally while keeping access, storage, session, and failure responsibilities separated.

- ✅ Independent local project identity and containment foundation.
- ✅ Protected repository primitives and validation tests.
- ✅ Operating-system secret integration foundation.
- ✅ User-controlled alternative access path foundation.
- ✅ Failure-closed handling for invalid credentials and altered state.
- ✅ Active-session lifecycle tests.
- 🚧 Complete end-to-end project setup and reopen interface.
- 🚧 Finalize interruption-safe explicit deletion behavior.
- 🚧 Finalize protected export and corruption-recovery choices.
- 🚧 Complete public-safe user documentation and acceptance validation.

Security implementation details remain private and are intentionally absent from this showcase.

## Milestone 3 — Complete interactive Kali terminal

**Status: 🚧 Foundation available; lifecycle hardening planned**

Goal: preserve a real local shell experience while making supported security-tool integration explicit and safe.

- ✅ Embedded xterm.js interface.
- ✅ Rust-managed PTY foundation.
- ✅ Interactive input, output, resize, interruption, and close paths.
- ✅ User-visible command submission.
- ✅ No automatic privilege escalation.
- 📋 Complete shell lifecycle hardening across failure and application-close cases.
- 📋 Make transcript-capture state explicit and disabled by default.
- 📋 Expand compatibility checks for standard Kali zsh and bash environments.

## Milestone 4 — Scope-checked Nmap capture

**Status: 🚧 Vertical integration available; hardening planned**

Goal: let users run supported Nmap commands normally while OrbitSEC validates scope and links resulting facts to their origin.

- ✅ Structured Nmap adapter and normalized observations.
- ✅ Controlled live-output foundation.
- ✅ Authorized target validation foundation.
- ✅ Provenance fields connecting facts to an operation and artifact.
- 🚧 Final command-review experience before enhanced execution.
- 🚧 Complete ambiguous-target and unsupported-command messaging.
- 📋 Persist the originating command relationship in protected project state.
- 📋 Reveal command provenance from selected visual facts.

## Milestone 5 — Explainable investigation guidance

**Status: 📋 Planned**

Goal: turn confirmed observations into useful next-step guidance without converting suggestions into automatic actions.

- ✅ Deterministic service-specific validation suggestions in the preview.
- ✅ Candidate-advisory labeling separate from confirmed findings.
- 📋 Expand evidence timeline and investigation notes.
- 📋 Add explicit hypothesis and finding states.
- 📋 Generate a reviewable investigation plan from confirmed observations.
- 📋 Add reporting views with traceable evidence references.

## Milestone 6 — OrbitSEC Copilot prototype

**Status: 🔬 Exploration**

Goal: demonstrate privacy-conscious, grounded AI assistance for learning and authorized lab analysis.

- 🔬 Build a provider-independent explanation interface.
- 🔬 Start with deterministic synthetic responses for UI and evaluation work.
- 📋 Support a small local model for private, cost-conscious labs.
- 📋 Explain selected hosts and services using bounded structured context.
- 📋 Summarize only user-approved notes.
- 📋 Cite the observation fields used in each response.
- 📋 Evaluate unsupported claims, scope drift, and observation/finding confusion.
- 📋 Keep remote providers optional and require explicit user action.
- 📋 Prohibit automatic terminal execution from model output.

## Later directions

**Status: 🔬 Exploration**

- Additional structured tool adapters after the Nmap pipeline is stable.
- Analytical graph and timeline views alongside the 3D universe.
- Sanitized, user-controlled report export.
- Reproducible CTF learning sessions using synthetic or explicitly approved material.
- Flashcards and study summaries derived from user-authored lab notes.
- Accessibility and performance testing on a broader range of Kali environments.

## Release principles

Every public milestone should preserve these principles:

1. Commands remain visible and user-initiated.
2. Active integrations remain within explicitly authorized scope.
3. Visual facts originate from validated structured evidence.
4. Suggestions and candidate advisories are not presented as findings.
5. Sensitive project material remains local unless the user explicitly exports it.
6. Public demonstrations contain only synthetic, reviewed material.
7. Security claims remain proportional to available verification evidence.
